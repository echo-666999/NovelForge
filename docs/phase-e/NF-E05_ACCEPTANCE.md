# NF-E05 受限修订、复评与人工介入验收

日期：2026-10-25。依据 PRD §13/14/15、UI14、AC11/15/20，A04修订/版本/证据/有限重试契约与 DEVELOPMENT_TASKS NF-E05。仅实现明确离线响应、受限补丁、作者选择及候选重取证复评；不调用真实模型、不处理中文分词，不推进E06及后续业务。

## 冻结输入与受限提案

- revision_tasks冻结同书、当前正文版本和完整E04评审哈希、选中问题、允许范围、原文、文风和评审策略。过期评审不能用于新任务。没有有效提取上下文时应先修正误提取，不能借文学修订掩盖无效证据。全部既有E03候选事实自动纳入保留清单，空preserve_facts不能省略它们；额外事件须属于本次提取，额外引文须精确匹配原文。
- paragraph范围沿真实LF换行边界；scene必须匹配本章唯一、完整的实际来源场景与版本；chapter必须作者明确选择完整正文，不默认整章重写。允许范围最多5段，逐段准确引用，不擅自扩大。界面默认准备首段后由作者确认问题和范围。
- 模型只输出patches：key、issue_ids、start/end、quote、replacement、reason，最多50项，每项原句/替换最多10000字符。补丁按原始正文Unicode码点位置递增、互不重叠，必须属于冻结范围和选中问题。一个问题可对应多个补丁；每个补丁内部不能重复问题ID，补丁key不重复。原句必须精确匹配，禁止响应自带策略、批准或正式状态字段。
- 每轮只允许一个不可变离线提案，失败原始输出与诊断保留，不能采纳。提案不会改正文。原始列表不重排，选择后按原始坐标逆向拼接，避免先改前文造成后文坐标偏移。派生替换仅规范CRLF/CR为LF，不trim/NFC；原始响应继续保留。
- 所有当前章节事件证据和作者额外保留引文受原句保护：补丁不能切断、删除或减少必须保留的引文。新正文重提取后，事件状态、事实类别、时间、主体/持有者、知识使用、依赖/知识/关系/伏笔关联的语义指纹和多重集合必须保持；局部引用键可变但不能改实体值。另核对真实证据派生的叙述顺序，不能用集合相同掩盖因果倒置。这里只比较显式结构化提取，不宣称证明了未提取事实或自然语言同义改写的语义等价。

## 明确采纳、手工编辑与完整章节复评

- revision_proposals保存原始响应、哈希、范围报告和可选注册运行/精确产物。逐项采纳只选择本轮有效提案中的patch key；手工编辑仍使用同一冻结范围和保留约束。两种采纳都调用既有E02候选编辑，在同一事务新建chapter_version并追加revision_decisions的完整前后正文/补丁/原因，绝不覆盖旧版或把采纳当作正式提交。
- 段落或场景只是章内允许改动范围，采纳后形成新的整章候选；原场景来源版本作为历史来源保留，不声称已改写原场景版本。拒绝或放弃不删除提案/原文；采纳后也可明确放弃，保留已创建候选及全部决定历史。放弃会使该候选的旧评审失去资格，不能借旧PASS继续提交。
- 采纳后状态为reviewing，必须显式提交针对新正文的extraction_output与完整章节review_output。复用E03实际章正文注册与精确新证据、原前章基线及作者规则；不重绑旧parent/偏移。revision_validations先保存新提取和事实保留结果，再调用E04七维整章评审，冻结前章衔接、原计划/作者约束和同一文风/策略。新任务须采用已发布策略；任务创建后退役不改此轮策略，复评继续核对冻结阈值和文风哈希。
- E04快照对E05新候选额外验证revision_validation与当前extraction_id精确绑定。即使绕过工作台另行提取并给高分，没有有效保留验证也不能PASS；删除事实或保留失败时，高文学分和人工评分均不能冲掉硬门禁。新评审与revision_assessments在一次事务中落盘，失败不能留下半份重取证/复评链。所有旧评审、失败和差异保留。
- 平均分不以浮点数存档，改善用七维总分增加或阻塞项减少判断。无改善时即使当前分数已达线也转manual_required，不自动视作修订成功。作者可明确确认已通过全部硬门禁且达到文学最低线的非阻塞候选：追加人工确认，不改原评分/失败。低分未达线或事实保留失败仍不可确认；也可人工编辑、重新评分或放弃。问题是否真正解决标为requires_author_confirmation，不伪称规则证明了文学改善。
- accepted只表示修订候选经复评或明确人工确认可继续，不是成品认可或Canonical Commit。后续提交必须同时检查修订选择/确认、当前完整E03/E04及其他提交门禁，不能只看一个历史PASS。

## 有限自动轮次、预算与恢复

- 默认最多3轮，取首次自动任务冻结策略上限且绝不超过3。获准自动的任务创建时即保守预留一轮，拒绝或未执行不退还；manual_required准入记录仅显示拟用轮次，不执行或重复预留请求；本章新幂等键、新评审、新任务或策略换版不能重置计数，技术attempt_no独立。上限0可禁用自动轮次。达到上限、无改善、硬门禁失败或前轮已要求人工时，不再执行自动补丁。人工编辑不消费自动轮次，但仍受来源/范围/事实和复评门禁约束。
- 注册revision.propose / revision-v1，generation队列；只允许fake供应商与精确冻结的RevisionReplayAdapter。C04仅为评审和修订允许复用drafting.scene的同一文风ID，未放宽其他阶段；完整问题、范围、原文、保留事项进入冻结上下文，D06容量不足拒绝、不能裁剪强制条目。字节估算不是实际Token或中文分词。
- C01租约/fencing、C02 outbox/回执、C05本章generation预算和加密请求证据保持。网关在完成事务外执行；产物、提案和阶段完成同事务。成功只产生待选提案，不自动采纳。独立进程恢复复用已核销响应，不重复请求、提案或文学轮次。
- 零预算deferred，不建请求、不造空检查点，工作台转人工；纯离线验证入口与预算运行明确区分，同一轮已有网关运行后不能用旁路提案覆盖。范围/保留错误保存失败提案并blocked/REVISION_SCOPE_BLOCKED，不能以技术重试凑结果。C06显示当前文学轮次和执行器接线，并重验冻结来源。暂停、取消、未知费用、书级串行槽和迟到隔离规则保持；人工编辑不自动取消旧运行或释放其书槽，需要按既有C06明确处理。

## 接口、UI14与数据库

| 实际接口 | 行为 |
| --- | --- |
| GET/POST `/api/v1/novels/{novel}/revisions` | 最近50条历史 / 冻结新任务（201） |
| GET 同路径 `/{revision}` | 冻结问题/原文、提案、全部决定差异、复评与当前有效性 |
| POST 同路径 `/{revision}/propose` | 验证明确离线补丁，不写正文（201） |
| POST 同路径 `/{revision}/runs` | 冻结路由/预算并启动离线阶段（202） |
| POST 同路径 `/{revision}/decide` | 逐项采纳、手工编辑、拒绝或放弃（201） |
| POST 同路径 `/{revision}/assess` | 新正文重提取、保留验证及完整章节复评（201） |
| POST 同路径 `/{revision}/confirm` | 明确人工确认已达线的非阻塞候选（201） |

写操作均要求Idempotency-Key和原因，保留同源会话/CSRF、管理员/同书授权、private/no-store。相同规范载荷重放首次响应，异载荷409；重放不冒充最新资格，需重新GET。A04 revision-runs示意细化为以上任务/选择入口，未注册示意路径不应视为可用。

创建字段：review_id、issue_ids、allowed_scope（kind/ranges，可选scene_version_id）、preserve_facts、preserve_quotes、mode=offline/manual、expected_version（书级）、expected_state_version、reason。propose字段offline_output/reason；runs另加route_version_id及本章generation billing。decide字段kind=accept/manual/reject/abandon、expected_version（来源候选版号）、reason，采纳需proposal_id/patch_keys，手工需manual_output。assess字段extraction_output/review_output/reviewer_type/reason，confirm仅reason。未知字段拒绝，ID使用十进制字符串。

UI14 `/admin/revision-desk`提供冻结范围、必保事实、原文、逐项差异、勾选采纳、同范围手工编辑、拒绝/放弃、离线运行、文学轮次/人工状态、新正文完整复评及明确人工确认；链接E04评审中心查看证据。没有正式写入或强制PASS动作。

新增7张不可变表：revision_tasks、revision_task_issues、revision_task_facts、revision_proposals、revision_decisions、revision_validations、revision_assessments。问题和保留事件分别以关联表建立同书强外键，任务读取同时复核关联完整性，冻结JSON不替代外键。同书复合FK及插入触发器核对来源评审、实际章/父版本、精确网关输出、采纳后正文及新提取/复评来源；每任务最多一次候选采纳，放弃为追加记录。所有新增表/字段中文COMMENT，正式表和novels.state_version不由本轮更新。
