# NF-E02 场景正文、章节组装与候选版本编辑验收

日期：2026-10-24。依据：PRD §5/13/25、UI09、A04 正文哈希/可见码点/恢复契约和 DEVELOPMENT_TASKS NF-E02。本次只实现明确的离线响应回放，不调用真实模型，不处理中文分词，不推进 E03 事件提取、E04 评审或 E06 正式提交。

## 实现

- 注册 `drafting.scene` 与 `drafting-v1` 运行。一个场景一个持久运行，投递到既有 generation 队列，复用 C01/C02 的 outbox、租约、fencing、消费回执、每书串行槽及 C06 恢复决定。启动读取作者有效冻结计划，检查场景所属章位、POV、当前书级版本和场景候选版本；本章前面场景必须完整、当前有效，不能跳序。
- 后续场景冻结前场景的精确版本、正文哈希和全文，作为不可裁剪的作者候选衔接资料，不能当成角色获知证据。前文换版后，后续场景、引用它的章节及恢复预览显示 stale；旧正文、失败证据和费用记录保留。当前顺序入口按章处理，不提供整书自动连续生产或正式基线读取。
- 共用 D06 的组装实现，原始要求、蓝图、批准核心实体/世界规则/POV、场景计划、伏笔与终局均继续确定性注入。新运行分支尚无自己的候选记忆，不借用其他运行的数据。已有 D06 持久清单入口仍沿用原校验；E02 在运行创建前组装，把完整清单内联冻结到 `generation_runs.frozen_config.context`，不伪造步骤身份或提前建立虚假步骤。实际发送文本等于此清单 final_prompt，配置哈希绑定实际请求。
- 运行启动一次性冻结已发布 Prompt/文风/路由、模型能力、价格与 generation 预算；预算必须归属当前章节。UTF-8 字节估算保守检查输入+输出+适用单列推理+256余量，真实模型令牌及误差未知。备用模型显式切换时再次检查容量。响应仅允许 `DraftReplayAdapter` 回放冻结正文，哈希不符即拒绝；fake 供应商、offline_fake 模式和真实模型门禁保持。
- 网关响应照常经过 C05 预留、模拟核销与加密脱敏证据。已保存成功响应后中断可在新进程重领同一尝试，不再次生成请求。场景正文与成功产物、步骤结果在完成事务内一起落盘，过期或隔离结果不会写入正文版本。
- `scene_versions`、`chapter_versions` 仅追加候选版本，保存原始输入、规范正文、精确父版本、计划、生成产物或编辑来源、字数、完整性报告、操作者及说明。数据库校验实际正文 SHA256，复合外键隔离小说与节点，触发器禁止覆盖/删除；新增写入接入现有脱敏审计。`chapter_scene_versions` 保存有序来源，禁止重复引用，并校验同章、同计划与冻结场景位置。三个表全部字段有中文备注。
- 组装必须显式提交全部场景的最新有效完整版本，数量、顺序与冻结计划完全一致；从这些正文重新构造章节，用两个 LF 分隔，绝不追加到旧章节。相同命令重放首次结果；相同正文及来源重新组装也复用现有候选，不重复拼接。
- 编辑与自动保存共用节点级乐观锁，必须引用当前 source_version_id 与 expected_version。正文变化产生新 body_hash 和父版本，旧稿不改；只改标题也产生新版本，body_hash 按 A04 仍仅由实际正文计算。正文未变化时不制造空版本；自动保存不会推进书级正式 state_version、批准或提交正文。

## 正文协议与检查边界

- 仅将 CRLF/CR 规范为 LF，不 trim、不做 NFC、不换标点；原始输入另存 raw_body。拒绝非法 UTF-8；PostgreSQL text 无法保存零字节，因此显式拒绝而非删除。
- `body-lf-utf8-sha256-v1` 精确哈希实际存储正文。`visible-codepoint-v1` 排除 Unicode 空白、控制及格式字符，其他码点逐个计数；组合字符和表情可能占多个码点。这不是中文分词或模型令牌。
- 场景与章节分别使用冻结计划的 min/target/max 字数，报告数量、目标差值及上下限问题。检查占位章名、明确的提纲/待补充/模型自述模式，以及缺少完整终止标点的疑似截断结尾。异常正文保留为 revision_required 候选，不能进入完整章节组装；没有静默补写或裁掉失败正文。
- 此规则报告只能检查明确模式，不能保证识别所有语义自述、隐性大纲、文学缺陷或真实模型截断；`semantic_review=not_performed`。不得将规则通过或场景运行成功理解为评审通过、正式提交或人工验收。

## HTTP 与 UI09

实际入口统一在 `/api/v1/novels/{novel}/drafts`：

| 方法 / 路径 | 行为 |
| --- | --- |
| GET `/` | 章节/场景候选与正式区状态；筛选章节、状态、缺章、字数问题 |
| POST `/runs` | 冻结并启动单场景离线运行，202及run_id/status_url |
| POST `/chapters/{id}/assemble` | 从全部有序场景版本组装章节候选，201 |
| GET `/{scene或chapter}/versions/{id}` | 精确版本、来源、字数/完整性报告、当前失效状态和最近50版历史 |
| POST `/{scene或chapter}/{node}/versions` | 编辑现有候选版本，201；无变化复用原版本 |

所有写入要求 ASCII Idempotency-Key（最多128），actor+novel+command 域，相同规范载荷重放首次响应，异载荷409。节点编辑/组装 expected_version 为节点内版本号；启动 expected_version 为书级版本，并另带 expected_candidate_version。保留列表顺序，仅规范对象键，兼容 PostgreSQL JSONB 对象键顺序。所有接口与 Livewire 服务均执行管理员和同书所有权检查，沿用同源会话、CSRF、private/no-store；拒绝未声明的写入字段。

书内导航新增“候选正文”：列表展示章序、具体标题、场景、候选版本/字数、状态；正式正文独立只读区明确尚无正式版本。可以读取和比较完整版本、查看来源和规则问题、编辑并每15秒尝试自动保存、提示未保存与退出提醒。保存冲突保留编辑内容并显示错误，不覆盖新候选。提供明确标注的离线响应、冻结计划/POV/路由/预算选择、单场景回放、按当前全部场景组装章节和恢复证据入口。

UI09 中正式指针、提交时间、人工验收、问题等级及评审状态的实际业务仍由后续任务实现，此处显示未实施/未验收，不虚构状态或提供提交按钮。UI10 阅读器、E05 定点修订、E06 正式提交均未推进。
