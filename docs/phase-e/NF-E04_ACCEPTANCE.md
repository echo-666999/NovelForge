# NF-E04 结构、文学七维评审与文风策略验收

日期：2026-10-25。依据 PRD §13/14、UI13/UI27、AC03/11，A04 正文/证据/评审有效性契约及 DEVELOPMENT_TASKS NF-E04。范围仅为显式离线响应、人工评分记录和确定性硬门禁；不调用真实模型、不处理中文分词、不推进 E05 修订或 E06 正式提交。

## 实现与门禁

- 实际候选章必须绑定同书同版本的 E03 完整提取，而非仅使用 D02 子报告。正文、body_hash、前章候选基线、事件/补丁、状态上下文、冻结计划、作者要求及实际生成文风进入评审输入。validation_hash 绑定 E03 输入/响应/完整报告和候选事件/补丁，context_hash 绑定完整评审上下文，input_hash 同时绑定策略版本及阈值。
- 结构门禁复用 E02 完整性/字数/占位符/正文来源与 E03 引文、批准实体、知情、时间、物品、能力和伏笔检查。缺失或失败、过期 E03、文风来源不明或不一致均阻塞；高文学分和人工评分不能抵消。准入来源错配直接拒绝，已接纳的响应结构/引文错误保留原始输出及阻塞诊断。
- 固定七维：情节推进、人物一致性、因果连贯、节奏、对白与声音、自然度、章节吸引力。每项1至5整数、理由和实际原句必填；禁止只有总分、漏维度、未知字段。默认各项≥3、平均≥3.8、阻塞项0。C04 Schema 子集只负责结构/类型/大小，数值范围、分类和严重度由评审业务门禁复核，不扩张通用网关协议。平均阈值及报告平均分按项目契约存十进制字符串，不用浮点数参与规范化哈希。
- 结论由服务计算，响应不能指定PASS。任何structure问题或blocking严重度都阻塞；低分项保留原句与局部修复建议。规则提示本身不自动降低评分、删除表达或变成硬冲突。所有通过都只是候选资格，human_acceptance与canonical始终false，不能作为正式提交或十章作品验收。
- review_policy_versions 不可变保存稳定键/递增版本、明确原因、七维阈值、重复规则、例外和正文文风版本；review_policy_states 追加发布/退役历史。默认修订上限3，字段仅供后续E05使用，本轮无自动文学修订。阈值降低只能显式追加策略版本和原因，不能覆盖旧结果；新运行必须选择已发布版本。退役阻止新采用，不改写已冻结结果。
- C04仅对 review.chapter 提示词允许精确复用 drafting.scene 文风版本，其他阶段匹配门禁保留。运行再核对路由、策略及实际正文场景来源为同一文风ID，内容相同但版本不同也不视为等同。无法追溯文风的手工来源不会猜测通过。
- reviews、review_issues、review_issue_decisions 保存不可变历史与可定位证据。仅非阻塞文学提示可追加人工接受/拒绝及原因，不能修改原评分/报告，不能接受结构或阻塞问题。数据库触发器也禁止硬错误豁免、跨来源引文、提取正文错配和伪造网关产物绑定。
- 正文换版、提取被替代、前章基线变化或完整上下文失效均使旧评审派生为stale；旧正文、原分数与失败不删除，不将旧引文重绑新正文。幂等键精确重放首次结果，查询当前资格必须重新GET。

## 文风提示与人工评分

规则层不使用分词：字面模板短语/禁用套路、重复短语与句式开头、重复对白、句长变化、前章相同开头/结尾均给出Unicode码点左闭右开位置、原句、解释和局部建议。例外来自明确新策略；重复对白只能提示人物同声风险，不能据此证明说话者相同或语义问题。模型层通过显式离线响应保存七维理由与定位问题，文风全文、节奏偏好及授权样例进入冻结上下文。

人工可在同一界面明确选择本人阅读评分，仍需七维原句与理由，并受同样硬门禁约束。自然度人工评分标志不等于成品认可。本轮夹具分数不是实际文学评测；尚无真实十章人工阅读评分、两段真实跨章对照或真实模型效果结论，不使用商业AI检测器概率。

## 离线阶段、接口与页面

注册 review.chapter / review-v1，使用review队列、C01租约/fencing、C02 outbox/回执、C04冻结配置与C05章节review预算。D06组装完整正文与硬条目，容量不足拒绝，不裁剪强制信息；UTF8字节估算不代表实际Tokenizer误差。只有fake供应商和精确匹配冻结响应的ReviewReplayAdapter可执行；真实接口门禁保持。网关请求与模型证据在完成事务外获取，产物、评审和阶段完成同事务。

零预算deferred、不创建请求，不以空结果伪造检查点；文学未过线标为blocked/LITERARY_REVIEW_BLOCKED，硬错误标为HARD_CONSTRAINT_BLOCKED，不能走自动或显式技术重试凑分。进程恢复复用既有已核销离线响应并重验来源；C06预览同样校验评审完整上下文，保留未知费用和旧失败。

| 实际接口 | 行为 |
| --- | --- |
| GET `/api/v1/review-policies` | 策略及派生生命周期列表 |
| POST 同路径 `/save`、`/publish`、`/retire` | 新版本、发布或退役；须明确原因 |
| GET/POST `/api/v1/novels/{novel}/reviews` | 最近50条历史 / 同步离线验证或人工评分，201 |
| POST 同路径 `/runs` | 冻结并启动明确离线评审，202与运行地址 |
| GET 同路径 `/{review}` | 原始响应、冻结输入、完整评分与问题及当前资格 |
| POST 同路径 `/{review}/decisions` | 追加非阻塞文学提示意见，201 |

写入要求 Idempotency-Key，沿用同源会话/CSRF、管理员及同书授权、private/no-store。同步字段为 chapter_version_id、body_hash、extraction_id、policy_version_id、expected_version（书级）、expected_state_version、offline_output、reviewer_type=offline/human、reason。异步入口移除reviewer_type，另加route_version_id与billing；billing.category=review且chapter_id精确匹配。评分响应为scores七维对象与issues列表。原A04 review-runs示意在本轮细化为以上同书入口，未注册示意路径不应视为可用。

UI13/UI27入口 `/admin/review-center`：原文只读、正文/上下文哈希、七维理由与原句、硬冲突/文学问题、历史有效性、PASS/BLOCK/stale与评审者筛选、严重度/类型筛选、离线发起/回放、人工评分和非阻塞意见；策略新版本/比较/发布/退役及文风全文可查看。使用选中策略评审实际样章，不把策略发布冒充文学回归。没有修订、强制PASS或正式提交动作。
