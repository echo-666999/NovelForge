# NF-E03 正文事件提取与硬约束验证验收

日期：2026-10-25。依据：PRD §7/12/13、UI16、AC11–14，A04 正文/证据/候选状态/恢复契约与 DEVELOPMENT_TASKS NF-E03。范围仅为明确离线响应回放、实际候选正文取证及确定性验证；不调用真实模型，不处理中文分词，不推进 E04 评审、E05 文学修订或 E06 正式提交。

## 正文、提取与不可变来源

- 以 E02 的实际 `chapter_versions` 为提取单位。章节必须是当前最新、完整且计划/场景来源有效的候选，必须显式提交正文版本、body_hash、预期书级输入和正式状态版本。场景通过 E02 的有序组装进入章，E03 不假造章正文或用摘要替代原文。
- D01 `source_documents` 增加同书复合外键 `chapter_version_id`，chapter与artifact两种来源严格互斥；只对新章节来源允许run_id/artifact_id为空，不伪造模型运行。数据库触发器从真实版本重验正文换行和UTF8字节哈希，既有artifact来源与Unicode证据校验保持。
- `extraction_attempts` 追加冻结输入、批准实体身份/定义哈希、规则上下文、伏笔计划身份、正文/前章基线、原始离线响应、哈希、报告、候选上下文及可选网关产物来源。`extraction_events` 映射局部键与真实候选事件；`extraction_foreshadows` 只登记候选变化。全部记录不可变、同书复合外键，数据库核验事件证据与本次正文来源，重提取父记录不得更换正文，父/基线不得形成环；网关产物必须属于本章、本哈希和注册提取运行。
- 提取结构或引文错误以保存点回滚临时事件、补丁、上下文和对应审计；外层仍保存原始失败响应及声明位置。诊断中的claimed_evidence是未核验声明，不能作为有效证据。规则冲突/待确认保留候选事件与可定位报告，不升格正式事实。
- 同一正文误提取使用parent_id另建记录，原文和旧失败不改。新正文必须新提取，不能重绑旧事件；同正文较新的有效提取替代旧候选资格，依赖它的后章也动态stale。幂等命令重放首次响应，当前资格须重新GET，不以旧响应作提交依据。

## 硬约束与定位

- 引文严格复核source_hash、UTF8 Unicode码点左闭右开范围和实际切片；非法UTF8/零字节在编码/写库前拒绝。事件只能引用当前书已批准且未退役的设定版本，不能由提取器创建或自动批准核心实体。对已登记的未批准/退役名称做实际正文的字面扫描，避免只靠漏报事件绕过。
- 后章必须指定紧邻前章当前有效的候选提取，累积候选事件/知识/依赖；不能以空基线忽略死亡、物品或秘密。当前没有正式基线读取和候选转正式能力。
- D01生成proposed_events/proposed_state_patches并复核哈希。D02继续区分客观事实、隐藏真相、信念、传闻、谎言和推测；不以置信度分数把待确认候选升级为事实。未知时间为ambiguous，实际时间合法倒叙允许，确定冲突为conflict。
- 复用D02死亡后行动/无解释复活、同刻异地/旅行耗时、物品双重归属/交接、能力上限、关系变化事件与知识获得路径。规则数值仅从作者显式选择的既有规则上下文读取，冻结具体版本；模型响应不能包含rules或覆盖原有规则。
- 叙述顺序由真实证据位置派生，不相信响应数组顺序。原始响应列表保持原样存档；派生次序用于验证。秘密使用必须属于该事件角色，获得路径须在此句之前，不能用同章后文的获得事件、重排响应列表或重叠引文提前授权；推测路径不能当作确定知情。冲突同时定位使用句、来源事实和获知证据。已知隐藏事实的字面披露必须登记uses，不能省略引用关系绕过。
- 伏笔变化须引用同书同蓝图当前冻结计划，事件证据必须来自本章；埋设、强化、回收需符合作者窗口，强化还需命中冻结强化安排，强化/回收必须有前置候选埋设，前置事件不能用计划替代。对作者隐藏含义提前字面披露做阻塞检查。模型不能改期/放弃计划，也不写D03正式occurrences。
- `eligible/current_eligible`仅表示本次明确提取数据的候选硬门禁通过，不能证明语义提取完整或文学质量。字面扫描不能保证识别新名字、所有别名/同名歧义、代词归属、同义泄密或隐含冲突；本轮没有真实模型语义评测。E04/E06不得只看D02子报告，必须绑定本章、本哈希且当前有效的E03完整报告。

## 离线网关、预算和恢复

- 注册 `extraction.events` / `extraction-v1`，使用既有generation队列、C01租约/fencing、C02 outbox/消费回执和每书串行槽。配置、Prompt/文风、模型能力、报价和generation章节预算在启动时冻结。模型协议为有界结构化事件/依赖/知识/关系/伏笔响应，value采用字符串；纯验证回放另支持D01既有JSON状态值。
- 实际正文、批准定义全文、作者规则、原始要求、前章候选证据与伏笔身份进入作者分析区，不能当作角色已经知道的信息。清单的final_prompt精确等于实际网关请求文本。C04会对JSON变量进行转义；解码变量可还原原始正文，不用“裸正文必须原样出现在提示词字符串”替代真实发送校验。
- 复用D06 ContextComposer做容量检查；硬条目不裁剪，UTF8字节估算输入+输出+适用单列推理+256余量，实际模型Token/误差未知。备用模型仍需显式批准并重验容量。fake供应商、offline_fake路由和精确冻结的ExtractionReplayAdapter是唯一可执行方式；真实供应商门禁未开放。
- 请求在完成事务外经过ProviderGateway、C05预留/模拟核销与加密脱敏证据。Usage为模拟，not_billable_fake，不代表真实费用。零预算不建请求，只deferred；没有有效事件时不伪造可复用检查点。来源变化、请求结果未知、费用未决门禁保持。
- 响应产物、候选事件/报告和阶段完成同事务。结构化响应获取成功不等于硬约束通过：硬冲突或待确认使阶段blocked/HARD_CONSTRAINT_BLOCKED，候选证据保留，不做自动/技术重试。仅误提取应保持正文、提供修正响应新提取。
- C06对注册E03运行的reextract准备精确正文/哈希/父提取与编辑入口，结果为awaiting_offline_response，既不假装已重新调用，也不重写正文。旧test.echo等reextract支架仍保留原限制；不得把E03章节来源交给testing-only旧提取器。被阻塞的运行仍保留书槽，另开队列运行前须按C06明确处理旧运行，不能悄悄删除失败或释放约束。
- 另外提供同步的纯离线响应验证入口：同样的来源、事件与硬门禁，仅做数据库内确定性回放，不创建虚假模型请求或费用。它和模型阶段使用相同候选验证服务，界面明确区分两种动作。

## 接口及 UI16

| 方法 / 路径 | 行为 |
| --- | --- |
| GET `/api/v1/novels/{novel}/extractions` | 最近50条提取历史及当前资格 |
| POST 同路径 | 显式离线响应验证，201，包含失败报告 |
| POST `/api/v1/novels/{novel}/extractions/runs` | 冻结并启动离线网关阶段，202和run_id/status_url |
| GET `/api/v1/novels/{novel}/extractions/{id}` | 精确响应、冻结来源、事件/补丁/伏笔及stale资格；也可导出JSON |

写操作必须Idempotency-Key（可打印ASCII，最多128）；actor+novel+command隔离，相同规范载荷重放首次结果，异载荷409。会话、CSRF、管理员与同书授权、private/no-store沿用现有协议。未声明字段拒绝，ID输出十进制字符串。来源/并发准入错误直接拒绝；已接纳的提取内容错误保存为阻塞记录。

验证字段：chapter_version_id、body_hash、expected_version（书级）、expected_state_version、parent_id?、baseline_id?、rule_context_id?、offline_output、reason。阶段启动另加route_version_id和billing，billing.category=generation且chapter_id精确匹配。offline_output固定包含events、dependencies、knowledge、relationships、foreshadows。事件必含key、definition_version_id、fact_kind、action、attribute、value、confidence、time、reason、evidence、uses；holder/修正目标和活动、地点、能力等为按需字段。局部事件引用local:key，前章引用event:十进制ID，不能引用任意书或同章旧提取的事件。

书内入口“正文提取与硬约束”进入UI16候选账本：实际原文只读、完整历史/哈希/原因、事件时间与叙述位置、事实类别/实体筛选、补丁和冲突证据；可回放截至章、重建当前有效候选投影、导出来源、准备只重提取。离线路由/预算/报价与回放动作独立提供，运行状态不会冒充硬门禁通过。正式事件和正式伏笔状态仍关闭，没有评审或提交按钮。
