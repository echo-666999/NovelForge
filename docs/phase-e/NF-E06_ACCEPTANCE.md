# NF-E06 Canonical Commit 原子提交与幂等验收

日期：2026-10-26。起始基线：`1f13996b90a2888696e4cbf86bb89ebd1f8a81c9`，起始工作区干净。依据 PRD §8/20、A04 §5、DEVELOPMENT_TASKS NF-E06、UI15及AC09/10/11/12/17。本轮只实现根基线顺序正式提交；不调用真实模型、不处理中文分词，不实施E07消费者、E08导出或G01历史重基线。

## 正式写入与校验

`CanonicalCommitService`为唯一应用正式写入口。首次显式空根初始化只确定基线身份，cursor/local_state_version/state_version仍为0，不产生正文/事实、不推进row_version；它不是基线切换。当前根基线version=1，已有非空状态不能重新初始化空根。

提交锁序为小说→活动基线→目标章。同书幂等键先匹配原请求：同规范载荷返回原提交及replayed=true，不先按后来游标拒绝合法重试；异载荷IDEMPOTENCY_CONFLICT。不同键竞争同一预期版本，仅一个事务推进状态；另一个STALE_STATE。数据库唯一约束进一步保证同基线章/序和同书提交键只生效一次。

预检保存不可变ready/blocked报告，失败原原因保留，报告不授权豁免。正式命令与ready预检除validation_artifact_id外必须完全相同，包括reason，并在锁内重验依赖哈希及下列条件：

- 当前活动基线和全局/局部正式版本一致，只提交cursor+1；E03 baseline必须精确对应上一章真实正式提交，不能借候选前章或任意混入事件跳过正式前缀。
- 完整正文、冻结节点/覆盖/字数预算、全部计划场景及精确来源版本；源场景运行必须绑定当前预期正式状态，冻结输入哈希、final_prompt与实际渲染文本一致。
- 评审绑定当前完整正文及哈希、当前E03/计划/作者约束/文风/策略；硬门禁和文学阈值均通过，无阻塞问题。修改正文后旧review明确REVIEW_STALE；人工高分不抵消无效提取、修订资格或未批准实体。
- 明确E03事件与码点引文、批准实体定义、事实/信念类型、补丁与撤销、时间轴、知识获取/使用、关系和作者规则重新校验。在保存点内用保存的明确响应完整重验E03，比较事实值、原文与完整上下文后回滚临时数据；不只比较两个PASS，不排序列表掩盖差异，不调用模型。
- 伏笔仅由精确正文证据产生plant/reinforce/payoff，前置事件必须真实正式成立；按实际正式历史检查埋设/回收与到期强制项。候选发生、规划勾选不能冒充正式证据，到期缺项REQUIRED_FORESHADOW_MISSING。

事务原子写入：canonical_commits、canonical_chapters、章正式指针、story_events、formal-state-v1快照及实体/知识/关系投影、伏笔实际发生/追加状态、revision游标/局部版本、novels.state_version+1、审计和canonical_outbox。row_version不随提交改变。回执与状态哈希封存；关系快照呈现当时有效事实关系，关系历史保留，推测/信念不升为事实。

数据库同书复合FK、唯一索引、写入证明和延迟完整性触发器替代D01/D03的永久CHECK(false)。缺少映射、快照、章指针或outbox的building提交不能完成物理事务。正式回执、事件、快照及其投影不可改删；冻结结构只允许精确匹配在建提交的两项正式指针更新，不能借此编辑规划。

## 最小兼容接入

正式指针从结构内容哈希排除，避免提交改变原冻结计划身份。B05仅允许在活动正式版本一致时继续只读消费既有冻结窗口，原规划写入/历史修改门禁保留。前章已提交E03记录可作为不可变正式baseline，即使candidate current_eligible已因state_version改变而为false；不将旧候选重新标为有效。

D01当前及指定历史章读取只解析正式映射，未提交的显式章404，不回退候选。回放使用正式事件及该次提交绑定的D02上下文，核对原快照哈希，不写入新快照。D03账本读取真实正式发生/状态，不再恒报未接入；主支线闭合与终局总门禁仍按后续任务。E02正文读取附真实formal元数据。

C02的运行outbox要求真实generation_run；本轮另存每commit唯一的不可变canonical_outbox，不伪造运行、外部请求或费用。事务中无网络/Redis/模型调用。目前仅持久保存pending意图，E07没有发布、消费或更新正式记忆/索引，不能把pending解释为已完成这些工作。连续两章测试为显式离线组装/取证/复评后提交，不代表生产连续编排或正式记忆衔接已开放。

## 接口与UI15

完整字段和状态见[A04接口](../phase-a/A04_API.md)。保留CommitCommand所有字段，ID为十进制字符串；实际映射为event_artifact_id→extraction_attempts.id、validation_artifact_id→canonical_preflights.id、plan_node_version_id→冻结章节plan_nodes.id。对离线/人工提取使用真实不可变记录，不制造generation_artifacts。根初始化、预检、正式提交与只读历史/回放共7个HTTP路由，同源会话/CSRF、管理员和同书授权，private/no-store；未知字段、force与超范围标识拒绝。

`/admin/canonical-commit-center?novel=…`提供：

| 页面内容 | 字段/表格/筛选/动作及状态 |
| --- | --- |
| 当前正式基线 | 活动基线ID、连续章游标、正式状态版本、待E07意图数；空态明确无基线/无正式稿，可显式初始化空根 |
| 候选载入与预检 | 实际正文版、chapter/review/plan/E03 ID、expected revision/state、理由；载入当前依赖、预检、提交；ready显示拟写状态、哈希与事件数，blocked显示原错误和位置 |
| 历史与回执 | 正式序号、正文、提交人/原因/时间、前后版本、原命令及正式快照；查看回执，重复点击同键返回同回执；无force或原地修史动作 |
| 筛选与分页 | chapter/revision、ready/blocked/committed、预检错误码、日期范围；每页最多各50条，数量/上一页/下一页；筛选改变回第一页；无记录有空态 |

预检和回执在Livewire中Locked，载入不同候选/小说生成新请求键。作者改理由或依赖后必须重新预检；服务仍在提交时校验，不能靠篡改页面绕过门禁。自动化验证包含真实页面动作，不等同真实浏览器视觉/可用性验收。
