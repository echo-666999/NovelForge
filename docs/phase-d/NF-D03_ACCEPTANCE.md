## 规划与作者决定

每条伏笔有稳定 lineage_id 和递增 version。计划字段包括名称、表面线索、隐藏含义、读者误导、禁止提前揭示、终局因果作用、前置条件说明；首次埋设范围、强化窗口及每次新增信息/选择影响、目标回收章、允许回收范围；重要程度、必回收标记、保密级别、批准实体具体版本、预期知情角色版本、前置候选事件及蓝图/主支线版本关联。

- 埋设窗口必须早于回收窗口；目标章必须位于允许回收范围内。强化窗口位于埋设之后、回收之前，新增信息与选择影响均必填。系统验证结构完整性，不声称这些文字已获得独立文学质量认可。
- 实体引用必须同书且具体定义已批准、实体未停用；知情者必须为人物。知情范围只表达未来作者意图，不写 D02 知识事实，不可直接作为角色上下文。
- 前置事件引用同书 D01 候选事件，具有既有精确证据链；候选前置存在不等于正式前置满足。尚未出现的前置以明确条件说明记录，不能编造事件 ID。
- 蓝图必须为同书封存版本；主支线必须属于该具体蓝图版本。冻结进一步要求蓝图已批准，并重新核验实体资格。冻结保存 plan_id/content_hash/作者理由，原承诺永不改写。
- create 只建 planned 计划。改期只允许调整埋设/强化/回收窗口与强化安排，不能偷换隐藏含义、来源、必回收标记或伏笔身份。
- propose 只追加候选，不变更有效版本或到期提示。decide=approve 才生成下一版本；reject 仅保留拒绝决定。作者理由保留在候选、决定和新版本中。
- 放弃必须提供替代安排，并经作者批准生成 abandoned 版本。历史 planned 版本和原冻结仍保留。已放弃版本不再接受冻结或改期。
- 新版本不会自动继承旧冻结，旧验收承诺仍可追踪。第100章改为110章不能追认旧100章验收为通过。

命令使用小说行锁和 novels.row_version 的 `expected_version`，不改变正式 state_version。幂等键作用域为作者/小说/操作，相同键同载荷返回原结果，不同载荷冲突；先查幂等再比较版本。批准只能针对有效最新计划上的未决定候选，旧版本操作、重复决定和竞争写入不会覆盖历史。事务回滚不会留下成功业务审计。

## 调度和主支线

调度必须显式指定 chapter，返回 `schedule_basis=author_preview`，不是正式提交游标。未指定章时 due/overdue 为 null。生命周期仍为 planned/abandoned，due/overdue 是独立派生提示：活动计划在回收窗口内 due，超过窗口末章 overdue。目标前20章提示检查铺垫，前5章进入高优先级。没有真实回收证据时明确缺项，不自动改期、不执行生成或改写章节计划。

服务给出 `FORMAL_EVIDENCE_UNAVAILABLE`、`PREREQUISITES_NOT_FORMALLY_COMMITTED`、`OVERDUE_WITHOUT_PAYOFF` 等缺项及确定性核对建议；这不是已接入生成门禁的声明。D06/E06/G03 应消费实际正式前置和到期结果，并完成后续运行阻塞。

主支线读取最后批准蓝图的具体 blueprint_thread_versions 和 ending_contracts，也可通过接口指定同书蓝图版本；显示主/支类型、目标、解决方式、转折、人物弧、关联有效伏笔版本、终局窗口、最终选择及开放项。正式闭合与证据进度保持未知。B04 的 required_foreshadows 是文本承诺，不猜测按同名自动绑定 D03 谱系；最终终局完整映射和闭合门禁属于 G04。既有蓝图新影响报告说明作者计划需到本账本复核，历史报告不重写。

## 数据结构与索引

| 表 | 用途 / 约束 |
| --- | --- |
| foreshadow_lineages | 稳定身份，同书复合唯一键，只追加 |
| foreshadow_plans | 完整版本与规范哈希；谱系+version唯一；蓝图/主支线复合FK；书+目标章索引；building→sealed后不可修改/删除 |
| foreshadow_entity_refs | 相关实体/预期知情角色具体版本；同书实体定义复合FK；仅父版本building期间可添加 |
| foreshadow_prerequisites | 同书D01候选事件FK；仅父版本building期间可添加，封存后不可增改删 |
| foreshadow_proposals | 改期/放弃候选、完整候选载荷、理由和替代安排；同书计划FK，只追加 |
| foreshadow_decisions | 每候选仅一条作者决定；批准新计划同书FK；拒绝不得生成新计划 |
| foreshadow_freezes | 每计划一次冻结；数据库校验同书已批准蓝图、sealed/planned与哈希；不可改删 |
| foreshadow_occurrences | plan/event/evidence/commit/chapter_version/revision；事件+类型去重，书+计划+事件索引；正式写入硬关闭 |

occurrence.kind 区分 mention/plant/reinforce/explain/payoff；causal_role 与 new_information 为未来正式证据的必要结构，提及/解释不能直接等于因果回收。E06 必须先补强正式提交、正文、基线复合FK，核查事件与证据同一正文来源、状态转换与合法知识链，再通过唯一正式写入口开放；当前绝不允许仅移除 CHECK 就启用。

C07 审计触发器已覆盖计划、候选、决定、冻结的元数据。隐藏含义和完整规划载荷不放入通用审计摘要；账本作者区本身只有授权管理员可读。
