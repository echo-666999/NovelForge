候选配置以书行锁串行保存，`expected_version` 比较本书时间线版本号，不复用小说规划 `row_version` 或正式 `state_version`。先查命令幂等再检查版本：相同键、相同命令返回原版本；相同键不同命令冲突；竞争保存只能一个成功。时间修正、移除依赖、修改知识和规则都创建新版本，历史事件、证据、时间线和检测报告不改写。

## 双时间轴契约

叙述轴来自 D01 的 `chapter_sequence/narrative_order`。实际时间独立保存于当前版本的条目，不覆盖 D01 原始提取的 story_time；时间修正保留旧提取和旧时间版本。

`time` 字段：

- `kind=unknown`：clock/start/end 都为空；禁止同时提供猜测时刻。检测为 ambiguous。
- `kind=exact`：start=end。
- `kind=range`：start≤end，为有界可能发生时间区间；不将区间强行缩为中点或精确时刻。
- `clock=relative_seconds`：书内相对秒序，可以负数；一天为86400秒。
- `clock=utc`：UTC 整数秒或带时区 ISO8601 秒级日期（支持 Z、±HH:MM），保存时统一为 UTC 秒；拒绝无时区或无效日期。范围 ±10^12 秒。
- 不同 clock 不自动换算关系，返回待确认。审计 created_at 与故事时间独立。

依赖类型为 before（严格先于）、depends_on（先于或同刻）、contains（已声明时间窗口包含另一窗口）、simultaneous（精确同刻）。依赖图不得成环。只有区间能确定满足关系才判 consistent，能确定违反才判 conflict；重叠不明返回 ambiguous。contains 表示窗口包含，不能据此证明窗口内某一未指定精确时刻发生了另一事件。倒叙合法，判断实际先后不使用章序。

## 一致性规则

| 约束 | 确定性处理 | 未知情况 |
| --- | --- | --- |
| 生命 | 客观/隐藏真相中的 life_status 为 alive/dead；死亡后行动阻塞。复活需中间 alive 事件、具体批准规则版本与该版本中作者确认的 revival 限制 | 死亡与行动时间不可比或同刻先后不明则待确认 |
| 地点 | 同一角色精确同刻出现于不同地点阻塞；地点与能力等引用要求同书、类型匹配并已批准 | 重叠可能时间区间不直接认定同时出现 |
| 旅行 | 作者明确起终点及最少秒数，绑定已批准规则版本；最大可用间隔仍不够则阻塞，最小间隔足够才通过 | 缺路线规则、混合时钟、可能间隔横跨阈值时待确认 |
| 能力 | 角色行动的 ability_id + 正整数 ability_units，对照作者确认并绑定批准规则的上限 | 缺上限待确认；超上限阻塞 |
| 物品 | 同一物品精确同刻的不同 owner_id 阻塞；后续交接要明确 previous_owner_id 且匹配之前所有者 | 时间不能确定归属先后时待确认 |

`attribute=action` 是显式行动类型，不能以 activity=false 绕过生命约束；其他属性可明确标注为行动。location_id/owner_id 的状态值是实体十进制字符串 ID，服务重新检查同书及类型。life_status、location_id、owner_id 以事实类别隔离，角色的“以为已死”不改变客观生命状态。hidden_truth 参与作者侧物理校验，但保留独立类别，不自动变成角色已知。

限制配置由作者显式确认，引用某个已批准世界规则版本；系统验证版本资格、主体/目标类型和数值约束，**不声称自动理解自然语言规则，或证明用户填的数值与原文语义完全一致**。规则当前支持每次行动能力上限与明确旅行下界、复活解释；不是通用资源、疗伤、成长规则语言。

## 知识与关系

knowledge_facts 保存 knower_id、fact_event_id、acquired_event_id、method、source_knower_id。内容和获得事件须位于同一候选时间线；获得事件为该角色的客观事件，须有 D01 精确证据。内容来源不能在叙述上晚于获得事件，实际时间也必须允许先获内容再知情。

- witness：显式目击路径；结构和证据存在不代表自动证明引文语义支持该事实。
- told：转述者必须有更早叙述位置、实际时间可比的有效知识路径；无来源、循环自证或不明确时刻不能赋予可用知识。
- inference：保持推测类别，即使之后转述也不会升格事实。

POV 按目标章截取候选前缀再验证，不会提前应用未来更正或展示未来知识。任何前缀冲突或待确认使 `usable=false`，已知内容返回空；这是保守门禁，不表示该角色实际什么都不知道。角色自己的信念/传闻/谎言/推测单独返回，绝不混入客观知识。整个作者区不应直接用于模型上下文。

relationships 保存驱动事件、主体、对象、关系类型和变化后状态；必须由有效客观事件驱动且主体匹配。历史保存每次变化，POV 中按叙述位置选最新同类关系；只有角色对驱动事件已有合法知识路径才展示，不因“是关系当事人”而假设知情。动机、信任变化是否具有文学说服力不属于确定性验证结论。

## 数据库及 A04 映射

| 表 | 核心约束与索引 |
| --- | --- |
| story_context_versions | 书内 version 唯一、书内 command_key 唯一、规范 payload 哈希、不可变报告及原因 |
| story_time_entries | 同版本 event 唯一；同书版本/事件/地点/能力/规则 FK；时间类型范围 CHECK；书/版本/时钟/上下界索引 |
| event_dependencies | 同版本前后事件复合 FK，禁止自身依赖；依赖组合唯一；应用服务验证无环 |
| knowledge_facts | 同版本内容/获得事件复合 FK，同书角色 FK；知情角色/获得事件查询索引；转述来源 CHECK |
| relationships | 同版本驱动事件 FK，同书主体/对象 FK；禁止自身关系；事件关系组合唯一 |
| consistency_rules | 批准规则版本及主体/目标同书 FK；同版本类型/主体/目标唯一（NULLS NOT DISTINCT） |

A04 数据字典的正式 relationships/knowledge_facts 最终关联 canonical revision / story_events；当前实体使用明确的候选 context_id / proposed_events。正式提交结构未存在前不伪造 revision ID；E06 需在接入真实提交时扩展正式归属与写入事务。本轮 read/POV 始终返回 scope=candidate、canonical=false，不宣称正式历史知识已生成。

## 接口

均在现有 web 会话/CSRF/管理员及小说归属检查下；响应使用 data/request_id/version，私有读取 Cache-Control: private, no-store，ID 均十进制字符串。

| 接口 | 输入 / 返回 |
| --- | --- |
| GET /api/v1/novels/{novel}/story-contexts | 最近50个封存版本列表 |
| POST 同路径 | Idempotency-Key；expected_version、reason、entries 及可选 dependencies/knowledge/relationships/rules；返回完整新版本及检测报告 |
| GET 同路径/{context} | 不可变候选配置、事件证据、报告 |
| GET 同路径/{context}/pov | knower_id、chapter；返回该章候选知识、独立角色说法、可知关系、usable/status |

每类列表最多1000项；不接受未声明字段或重复唯一条目。INVALID_TIME、DEPENDENCY_CYCLE、DUPLICATE_CONTEXT_ROW、INVALID_RULE、MISSING_EVENT 为结构性拒绝；幂等/版本冲突返回409；权限与归属沿用401/403/404。旅行等可修正的内容冲突保存为不可变报告，不用 HTTP 200 冒充一致性通过。`report.eligible` 仅表示该候选确定性检查无待决项，不是生成或正式提交资格。

## Filament 逐页规格

页面 `/admin/story-timeline`，导航“创作管理 → 时间线与角色知识”。UI17 人物设定详情可跳转查看候选时间线，正式动态状态仍标记未建立。

- 版本区：小说、最近50个版本、保存原因、读取/重新查看报告。空态明确没有候选事件或尚未选版本；不会自动创建正文。
- 新建区：从现有候选事件多选建立时间线，初始时间全部未知。
- 事件表：事件编号、叙述章位、主体、事实类别、实际时钟/范围、属性/值、精确证据及码点位置。筛选人物、地点、时间类型、时钟、范围、仅问题、仅秘密。时间范围须先选时钟，避免混合时钟比较。
- 检测区：consistent/ambiguous/conflict 显示“一致/待确认/冲突”，列问题事件、修复建议。事件引文内联展开并 HTML 转义。
- 时间修正：事件、unknown/exact/range、时钟、起止、是否行动、地点、能力/单位、交接前所有者、复活规则；选事件时回填已有字段。保存创建新版本，不能修改历史。
- 依赖区：前置/容器事件、后续/被包含事件及关系；追加后检测。
- 知识区：知情角色、内容事件、获得事件、目击/转述/推测、转述者；查看指定章 POV，列获得章、途径、证据和独立说法。不可用状态明确提示。
- 关系区：驱动事件、主体/对象、关系类型和变化后状态；追加保存。
- 规则区：已批准规则、travel/ability/revival、主体/目标及整数限制；提示作者确认原文与数值的对应关系。
- 历史条目区：依赖/知识/关系/规则列表，可在新版本移除一项，旧版本仍保留。界面动作共用服务，不直接写表。
