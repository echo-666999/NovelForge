# NF-A05 验收方案与数据说明

本包是离线候选夹具与未来验收协议；所有AC用例目前not_run，AC22按用户CR001转为后期最低优先级。没有生成真实小说或调用供应商，不能将候选骨架当作百章已完成。

## 1. 三种证据严格分离

- 基础工程检查：A01中本次已有测试与环境查询。
- Fake/合成数据验证：本包原文、查询、事件故障样例；验证程序正确性与隔离，不验证文学质量。
- 真实成品验收：正式生成后另建批次，留真实模型请求、正文、review、commit、费用、作者评分。必须确认DECISIONS中的模型/预算/小说后再开始。

## 2. 检索集 v1

retrieval_corpus.jsonl含20组主题，每组1条合成正式来源和5条同文本诱饵：另一小说、未来章位、错误POV、旧基线、失效来源，共120条。retrieval_queries.jsonl含100条独立查询：精确20、别名20、同义情节20、错字20、短词/混合文本20。每条包含固定书、基线、截止章、POV、正相关来源（grade=3）和明确禁止来源。

判定：先过滤，再召回、去重、排名；每查询Recall@20=前20个唯一source_id中的正相关数/该查询已标注正相关总数；本v1每题1个正例，因此是可解释的命中率基线。宏平均≥90%，各类型单列，不因总体平均掩盖问题。禁止来源命中总数必须为0；其他未标注结果在v1按不相关计，人工新增相关标注必须发布新数据集版本。不能只用20条正例、不加载100条诱饵后报告隔离通过。

本集合是小规模功能基线，不证明真实长篇规模召回效果。D05需增补真实授权语料；性能按PRD单独测。向量/别名/trgm均可处理中文内容，**当前不依赖中文分词扩展或全文通道**；不强制所有通道均返回命中。分词预览、词典、tsvector及替换比较只在后期执行。

对未来知识还需运行AC13和AC08：静态检索诱饵不能替代角色获得知识的因果检验，到期伏笔必须由结构化账本强制注入。

## 3. 重点验收候选

novel_contract.json给出原创候选《雾城旧档》，100章以上计划、人物/秘密/世界规则、三条前5章伏笔与准确100章回收约束；ten_chapter_plan.csv有前10章具体标题/目标/冲突/变化/POV/伏笔任务；hundred_chapter_outline.csv为100章规划骨架（不是正文，尚未冻结或批准）。

正式AC01前仍需把前10章展开到Scene字段：时间地点、参与者、冲突、情绪起止、必须事件、禁止变化、字数分配和衔接，并通过B05覆盖/预算门禁。本轮不伪装为已经实施的规划流水线。原文样例与规划可作为候选调整，最终正文必须由后续真实流程生成并可由作者修订。

- 前10章：逐章2500–3500可见非空白字符；七维各≥3、均分≥3.8，严重冲突0；逐章人工全读，十章全部认可才通过。
- 百章：首次生成前冻结3条伏笔，其中铜钥匙在1–5章埋设、窗口100–100回收；实际连续正文1–100，不跳6–99、不写库假造paid_off。6/30/60/95章检查；回收前20章准备、前5章强制装入。
- 人工阅读埋设与全部相关强化及98–100，核对整链；五维各≥3、均分≥3.8。再提道具名称不算回收，必须造成有效选择或主线状态变化。

## 4. 故障矩阵

acceptance_cases.csv覆盖AC01–32的前置、步骤、预期和证据；fault_fixtures.json提供可直接据以写测试的结构错误、并发时序、hash过期、未知费用和注入文本样例。夹具不包含可执行脚本或真实密钥。实际故障注入仅在测试环境，不向共享Redis/业务库执行停止或清空。

## 5. 门禁与批次冻结

当前P0用例为AC01–21、AC23–32，共31项；AC21按核心检索口径，AC22后期。所有其他功能/权限/人工门槛保留。建立run manifest记录：PRD+CR版本、设计/数据集哈希、小说/计划/基线、Prompt/模型/能力/价格版本、预算、测试环境、代码版本、开始时间、操作者、批准记录。

模型选型、计费币种、单次/单书/日预算、嵌入维度和作者选定小说未决时，不发真实请求；这不妨碍离线设计完成。接受新契约必须新建验收批次，保留旧失败，不修改100章回收位置来获得通过。

## 6. 可填写记录与证据目录

forms/execution_records.csv：每个AC一行，实际执行后填写状态/命令/环境/证据路径；初始not_run不是结果。
forms/chapter_review.csv：10章×7维=70行；读者填写1–5分、依据片段、问题与复核，不预填分数。
forms/foreshadow_review.csv：3伏笔×5维=15行；重点百章伏笔必须全部填写，其他回收窗口独立核对。

未来证据根目录建议为私有storage下 `acceptance/{batch_id}/{machine,human,artifacts,requests,costs,exports}`，不是当前已创建目录。每文件记录SHA-256和来源身份；导出评阅包可编辑但签署后的评分快照另存不可变副本。凭据不进入任何证据包。

## 7. 判定规则

结构/Schema通过、文学AI通过、Canonical Commit成功、人工成品认可分列。失败用例保留原请求和拒绝结果；修复后新attempt。skip、deferred、unknown均不算通过；CR001明确移出当前P0的用例单列，不用skip冒充当前通过率。任何阈值变更需要测试前决定，不能在读完差稿后追认降低。
