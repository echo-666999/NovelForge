# NF-A02 备份补强与交付收口

日期：2026-10-29，Asia/Shanghai。用户授权仅补齐备份启动等待/失败重试、恢复一致性、任务总览与验证；未推进F01，未修改共享数据库或其他项目。

## 实现

1. **有界等待和重试**：取得独占锁后每次最多等待数据库60秒，单次探测有超时；备份最多3次尝试，间隔10/30秒。错误数据库身份立即拒绝。重复触发返回skipped；失败只记录次数与通用阶段，不打印连接密钥。耗尽后非零退出，保留既有备份。部分输出只在隐藏临时目录内，失败自动收尾。
2. **成功发布与清理分开**：新包完整后原子发布，再执行7天清理。清理失败明确记录`backup_retention_failed`并非零退出，不重复生成备份；v1/v2历史包均沿用已确认保留期，不覆盖旧证据。
3. **冻结备份校验清单**：v2包新增`verification`。表摘要与pg_dump共享导出快照；序列取归档实际保存的setval；私有文件摘要取自归档内容。恢复只与此清单比较，正常后续写入不会再造成“恢复不一致”的误报。
4. **独立恢复入口**：新增`verify_backup.py`，准确选择指定包，先检查文件哈希，再在本项目专用实例创建并清理`novel_forge_test`。已有同名库会拒绝覆盖；独占恢复锁防止重复验收。不会重启应用服务，也不会读取当前业务库或实时私有文件作为比较基准。
5. **兼容与收口**：旧v1备份保留，仍可按原运维流程恢复；缺少冻结清单时新校验器明确拒绝自动验收，不伪造历史清单。`verify-runtime.py`改为使用本次备份返回的准确目录及新验证器。任务总览更新至E08、UI14及A02当前状态，保留其他任务原状态与待办边界。

快照依据核对了本机PG18工具及官方[pg_dump快照参数](https://www.postgresql.org/docs/18/app-pgdump.html)、[快照同步函数](https://www.postgresql.org/docs/18/functions-admin.html#FUNCTIONS-SNAPSHOT-SYNCHRONIZATION)与[序列事务语义](https://www.postgresql.org/docs/18/functions-sequence.html)。序列变更不随普通事务快照冻结，所以不能用导出时另外查询的实时序列作为校验基准。
