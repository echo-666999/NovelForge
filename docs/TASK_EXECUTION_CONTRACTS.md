# 任务执行拆分与进入/退出契约

日期：2026-10-31。对应[任务总览 v1.7](DEVELOPMENT_TASKS.md)。本次只调整文档组织，不实施子任务、不操作业务数据、不改变已有授权边界。

## 共同规则

1. 原父任务编号、依赖、验收阈值、PRD/AC归属和历史证据全部保留。子编号是执行分解，不是新的产品范围或降级验收；父任务通过仍需原卡全部标准满足。
2. 下文“进入条件”在共同规则及父任务约束之上累加；“交付结果”是可核对的退出产物，不自动等于验收成功。每个子项的证据应注明环境、批次、输入版本、命令/动作、实际结果和未覆盖项。
3. 离线功能、真实调用、后台端到端、正式提交、人工认可、运行观察是不同证据维度，不互相替代。历史报告只证明当时范围；新批次核对适用性后引用，不为了拆分重跑所有已通过测试。
4. 每批执行前冻结排除范围、最大尝试/修订次数、授权及停止条件；未知值记“待确认”，不默认无限重试。出现未知请求结果、输入失效、越权、预算门禁或环境隔离问题时停止受影响步骤，保留原始证据。未知费用不记零、不重复发送；隔离后能否进行独立工作须按现有契约和授权核对。
5. 失败结束分为needs_changes（实现/输入问题）、blocked（依赖缺失）、human_pending（等待人工判断）；保留失败批次与恢复入口。结束失败批次不是accepted，也不通过降低评分、追改回收窗口或伪造正式状态求通过。
6. 创作内容只准备到冻结批次所需边界。遇到可保留未知的细节，不新增作者问答；遇到代码硬门禁则列出具体阻塞和范围选择，不能偷偷绕过，也不能无限扩写以消除阻塞。
7. 修改需求、模型政策、基线或验收输入时，按原不可变契约产生新版本/新批次；历史正文、失败、报价、费用与人工决定保留。恢复前核对输入哈希、授权、幂等键及可复用证据。
8. 技术测试仅用novel_forge_test和隔离队列/存储；开发库与其他项目不作为故障靶场。真实运行、故障注入、批准、发布、部署是不同动作，本文件不授权任何动作。
