设定内容从保存起不可变：事务内building→sealed只允许一次，后续UPDATE/DELETE拒绝；sealed只是存储状态，不等于批准。终局、主支线、实体及覆盖记录仅在building中写入，封存时核对数量和内容与快照一致；sealed后不能增补。检查与批准只能附于sealed版本，数据库要求批准引用该蓝图的匹配通过报告。历史检查、失败报告、批准证据不覆盖、不删除。

新版本总是追加base_version_id，并产生新的Ending Contract，旧批准记录继续可读。稳定Thread仍由B02管理，B04不原地改写它；保存时固定其名称/目标及本次主支线规划。后续工作树或Thread改变会使旧候选的依赖检查失效。

A04补充：本轮覆盖表是**蓝图专用**承接关系；B01/B05的requirement_coverages→plan_nodes尚未实施。B04绑定B02已封存outline_versions；不原地给旧结构版本添加蓝图引用。B05若建立反向蓝图关联，应在新结构版本中添加真实FK并保留旧历史。

## 手工规划内容

蓝图字段：故事一句话、长简介、世界概览、人物初始设定、卷弧结构及不可逆变化、节奏、信息揭示、能力边界、牺牲代价、伏笔规划、主要转折、人物弧、待决冲突。

主支线字段：稳定Thread、main/sub、目标、解决方式、转折、承接人物弧；同一蓝图不重复引用同一个Thread。至少一条主线，主线必须有解决方式，所有线索必须有目标。

终局字段：目标章数、允许结束窗口、主线解决方式、主角最终选择、关键人物结局（含生死）、核心反转/答案、最终关系、必回收伏笔承诺、允许开放事项、禁止的临时解法、完成证据要求。人物结局只能指向本蓝图绑定的人物设定，所有绑定的core人物须有结局承诺。

窗口必须包含小说目标章数，终局目标与小说一致；窗口末端可以大于目标，符合PRD的弹性结束窗口，不代表自动增加小说目标。未规划相关反转或最终关系时，应明确写明无相关承诺，不能留空假装完成。

必回收伏笔当前是规划文字承诺，不是D03账本ID或已回收事实；完成证据要求是未来证据标准，不是已有正文证据。

## 检查与批准门禁

`BlueprintService`共用管理员/小说归属校验、同源API错误协议、小说行锁、expected_version及命令幂等锁。每次写入必须有原因和幂等键，复用已有命令存储，不提前建设任务DAG。相同键同载荷重放原响应，异载荷409；归档不可写。

保存可保留未完成候选，但非法跨书引用、无效原文覆盖、重复引用、错误字段形状会立即拒绝。检查报告保留所有阻塞项，检查失败仍保存报告。批准必须携带检查ID、完整report_hash，并确认已阅读影响；服务在同一事务中重跑全部检查，不能用旧的成功报告绕过依赖变更。

检查包括：

1. 内容哈希、最新蓝图版本、原始来源、当前要求及实体资格、工作结构与绑定结构的一致性。指纹变化要求复制为新候选，不重绑旧报告。
2. 当前要求须来源有效、决定明确；偏好可保留B01中已有的作者waived决定，其余要求需蓝图字段准确引用。引用必须真实存在于所选字段，不能填任意说明或伪造引文。
3. 至少绑定一位人物，全部实体设定版本已批准且未停用。人物稳定设定的批准不等于正式动态事实。
4. 蓝图必需字段完整，登记冲突为空，主线目标/解决方式完整，终局窗口及承诺齐全。
5. 作者明确完成主动目标、冲突容量、独立动机、世界一致性、每卷不可逆变化、前十章场景可执行性六项检查。复制修改默认取消这些勾选，要求重新审阅。
6. 绑定结构具有前min(10,目标章数)章及各章至少一个场景。这里只做结构存在性检查；细节质量、场景预算和完整生成门禁仍由B05负责。

准确引用是可追溯的文本承接证据，不能自动证明文学或语义上充分满足原始要求。六项内容判断由作者承担，当前没有模型审阅或自动语义推理。

批准只追加审计记录。display_status按历史投影为draft/needs_changes/approved/superseded；新候选未批准前不撤销上一批准记录。旧批准之后若依赖变更，仍保留其历史批准事实，不把它视为当前可用资格；任何后续生成消费者必须重验依赖。当前所有蓝图均不可生成。

## 终局变化与影响

任意保存均产生新终局版本；生死、最终关系、反转或答案改变不会覆盖旧版本。impact记录变化分区、ending_changed、旧新绑定结构的保守卷/章并集及旧新伏笔承诺集合。

这是一份保守规划影响清单，不宣称已经证明某章正文一定受影响。canonical_text_impact和actual_foreshadow_impact明确为null，页面提示“尚未接入，不能判定无影响”。不能把未知显示为0或无需复核。批准前必须确认已阅读影响；后续正式历史修订仍遵循G/E阶段流程。

## 已实现接口

前缀 `/api/v1/novels/{novel}/blueprints`。同源会话与CSRF，A04统一响应包；ID字符串，时间带时区。POST均需Idempotency-Key、expected_version、reason。无权/跨书404，非管理员403，未登录401；校验错误422，旧状态/旧报告/幂等冲突409；CSRF可能先返回419。

| 方法 / 后缀 | 参数及结果 |
| --- | --- |
| GET / | cursor默认20最大100；status=draft/needs_changes/approved/superseded全局筛选；返回版本、终局、最近检查与批准历史 |
| GET /{blueprint} | 完整历史快照、影响报告、终局契约、最近检查与批准；核验content_hash |
| POST /save | outline_version_id、body、entity_version_ids、threads、ending、coverages、author_checks；始终追加版本，201 |
| POST /validate | blueprint_version_id；保存完整阻塞报告、依赖与规则指纹，200；passed=false也保留检查记录 |
| POST /approve | blueprint_version_id、validation_id、report_hash、acknowledge_impact=true；重验依赖并追加批准，200 |

数据数组具体项：threads含thread_id/kind/goal/resolution/turning_points/character_arc；coverages含requirement_version_id/field/quote；ending.outcomes含entity_definition_version_id/outcome。其余字段见上文。候选保存是完整快照语义，非PATCH；修改入口预填既有内容。来源由当前原始输入和绑定结构确定，不接受手填跨书来源。

A04原批准接口设计中的coverage_hash在B04细化为覆盖**整个检查报告**的report_hash，并绑定validation_id；报告包含蓝图content_hash（含全部覆盖证据）、依赖hash与检查规则版本。上表为实际已注册的所属页面CRUD，未宣称其他设计路径已实现。
