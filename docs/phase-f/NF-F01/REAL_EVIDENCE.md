# NF-F01 真实来源持久化与能力验收（2026-10-30）

本轮沿用用户对发布配置、启用供应商及真实请求的授权。设定和蓝图仍不批准，候选不自动采纳，正式剧情不自动提交。此记录补充并更新此前 STAGE_MODES 中的技术阻断说明；NF-F01 仍为 in_progress。

## 持久化契约

- 新增 `model_capability_evidence`，精确绑定模型声明版本、供应商版本、成功请求、原始响应证据及摘要。记录实际响应模型身份，禁止更新或删除。历史模型声明继续保持 `unverified`，不通过修改旧声明伪造验证。一次成功的结构化响应不证明声明的全部容量、流式能力或文学质量。
- `ai_requests.evidence_kind` 区分 `offline_simulation` / `real_provider`，`cost_status` 对应离线不计真实费 / 真实可计费。真实来源须绑定 production 冻结运行及 json_http 供应商版本。原始响应继续独立加密、脱敏保存，业务对象转换不会覆盖证据。
- 真实评审使用 `reviewer_type=model`，真实修订任务使用 `mode=production`；评审及修订提案的 `source_request_id` 必须对应同小说、同运行、同阶段产物的真实成功请求。原有正文哈希、冻结上下文、补丁范围和产物一致性校验继续生效。
- 离线和真实自动修订共用轮次上限；生产提案不能借手填离线输出旁路生成，不自动采纳补丁。产生真实记录后，迁移回退会明确拒绝删除这些证据。
- 新表及全部新字段均添加中文备注。费用列表、工作台汇总和CSV按证据来源区分真实与模拟；未知费用保持空值并保留风险预留。

## 受限真实发送

- `NF_REAL_EXECUTION_ENABLED` 默认关闭；本次小范围验收只在独立执行进程中开启，不开放全局无人值守外发。
- 请求必须已有持久身份、冻结 production 配置、成功预算预留、有效租约、未变化的正式状态及仍启用的供应商。发送内容须与持久请求证据逐项一致。
- HTTPS精确主机、公网DNS固定、禁止代理/重定向/自动重试、30秒配置超时、有界响应及迟到隔离规则保持不变。初期真实请求另限制为128000字节以内。
- 正常生产路由发布/冻结需要精确模型与供应商版本的能力观察证据。首次探测仅允许 `planning.intake`、单一模型、无备用模型、输出不超过4096 Token；只允许临时引用草稿路由，提示词和文风仍必须已发布。探测标志、模型、价格、预算、小说来源和管理员原因随运行冻结。
- 输入提炼仅携带原始创意与要求，不把无关整书结构及人物历史带入该阶段。后续阶段继续保留各自规划依赖。
- 真实响应模型或服务档位不匹配时不能按冻结价格结算，保留原始证据与风险预留。缺Usage、计量冲突、未知结果不推定免费，不自动重发。

官方计量参考：[Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)、[预算控制示例](https://developers.openai.com/cookbook/articles/per_run_spending_controller_responses_api)。本项目已配置缓存写入价格，缺失写入计量不能直接补零；推理包含在输出时不重复收费。实际账户权限、实际模型响应和费用仍以本次运行证据为准。
