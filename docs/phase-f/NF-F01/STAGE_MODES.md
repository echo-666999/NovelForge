## 已接线

- 五类服务覆盖9个注册阶段，接受 execution_mode=offline_fake/production；缺省继续兼容历史离线调用。
- 离线必须提供offline_output；真实请求严格禁止携带该字段。UI切换模式保留编辑内容但不提交离线响应。
- 新运行冻结execution_mode，模式参与请求幂等摘要；阶段模式须与已冻结路由一致。
- 五类执行器统一从冻结运行选择适配器；不使用Worker传入的离线输出替换已冻结响应。
- FrozenResponsesAdapterFactory只按冻结模型/供应商版本组装Responses适配器，不追随默认路由或最新端点。
- 提取阶段拆出prepareInput，真实分支准备正文来源、人物/规则约束和前章基线时不再伪造模型输出或创建临时候选事件；离线分支仍预演原响应。
- 规划、正文、提取、评审、修订后台均增加模式选择；路由选项按模式筛选，缓存键也包含模式。
- 真实模式不渲染规划离线响应编辑器，避免旧的无效离线JSON阻断真实入口；手填内容仍保留。
- 无DDL、无配置发布/启用、无真实请求、无正式剧情变化。

## 尚不能启动真实运行的具体原因

1. model_profile_versions.verification_status仍受数据库CHECK约束固定为unverified，尚无绑定供应商/模型版本的不可变能力验证证据。
2. AuthoringConfigurationService.routeSnapshot仍拒绝生产路由发布与冻结。声明“支持”不能替代实测能力，也不应把历史离线回归当作实测。
3. ProviderGateway及HTTP适配器仍只允许现有离线/Mock路径，真实运行资格尚未接到发送门禁。
4. reviews.reviewer_type与来源触发器仍限定offline/human，revision_tasks.mode仍限定offline/manual；提取来源标签及费用证据也仍有离线语义。需先完善真实来源持久化契约，再开放真实结果落库，防止混淆证据。
5. 当前蓝图未批准、滚动计划及计划冻结未建立；这些创作状态硬门禁与技术能力验证分开处理，不自动批准。

以上是技术与业务状态门禁，不是重新要求用户授权。实际发送应待这些门禁完成后按既有单章预算执行。
