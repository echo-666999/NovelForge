# NF-C05 Token计量、价格版本与原子预算验收

日期：2026-10-24。范围仅 NF-C05；真实模型、中文分词和 C06 运行控制未推进。

## 实际交付

- `price_versions`：每百万Token的五类原币单价、缓存/推理规则、币种、生效时间与凭证说明，版本递增且不可覆盖。价格必须显式填写，金额是十进制字符串；没有内置真实报价。
- `budget_policies`：请求、章、运行、书、日上限；预警与停发百分比；版本、原因及 UTC 日界。后台示例为80%/100%，服务要求显式录入。新版本供新运行采用，不能改写旧运行。
- `budget_buckets/budget_reservations/budget_allocations`：跨政策共享的预算桶、单请求最坏预留及桶关联。新政策键或版本不能清零旧书/旧日支出。请求额度直接检查，章/运行/书/日桶按固定顺序锁定。
- `usage_settlements/billing_identities/cost_ledger`：追加式核销、供应商计费身份去重、五类明细和冲正历史；重复Usage不重复结算。更正追加上一版本的反向流水和新费用，旧证据不变。
- `billing_commands`：管理员配置及对账幂等。网关请求新增 `price_version_id` 外键；所有新表和新增字段均有中文数据库备注。

## 冻结、预留与核销规则

测试运行新增 `billing` 输入：`policy_id, price_version_ids, chapter_id?, category, max_output_tokens, max_reasoning_tokens`。主备模型价格必须齐全、同币种、已生效，输出上界须与路由一致。旧无预算的纯编排支架仍可运行，但不能调用网关。C04配置中的价格引用由新的运行冻结逻辑填入，旧C04快照保持原状。

节点可带 `billing_scope={chapter_id?,category}`，用途与章节进入不可变依赖图。同一运行可包含多个章节及用途；缺省采用运行归属，没有章节时共用本书 unassigned 章预算桶。所有章节必须属于本书。用途支持 generation/review/revision/summary/embedding/planning，共用同一网关预算门禁；尚未实现的实际创作/嵌入业务没有在本轮提前开发。

最坏预留采用声明上下文容量的保守上界，输入空间扣除最大输出及仅在独立计费时适用的推理预留。缓存类别使用最高适用输入单价，并补足分项向上舍入的余量。每类费用向上保留十位小数；预算百分比阈值向下保留十位小数，防止四舍五入放宽停发线。全部运算在 PostgreSQL numeric 中完成，金额列为 numeric(24,10)，PHP不使用浮点核算。

请求创建、冻结价格、最坏费用预留和请求证据同事务提交，任一额度不足整体回滚，传输尚未发生。网络执行期间不持有预算锁。每桶必须满足已核销实际费用 + 未核销预留 + 新预留不超过冻结停发上限；已有暴露达到停发线也拒绝新请求。拒绝返回 `DEFERRED_BUDGET`，既有测试阶段驱动将它持久化为 deferred；没有自动追加额度或自动重试。本轮没有实现 C06 的其他失败分类、暂停/恢复界面或人工决策。

计量规则：

| 规则 | 归一化 |
| --- | --- |
| cache=none | 缓存字段缺失按不适用处理；非零缓存反证会阻塞核销 |
| cache=included | input_total减去cache_read/cache_write，再分别计费 |
| cache=separate | input已经是非缓存输入，缓存另外计费 |
| reasoning=included | output已含推理，仅按output计费，不再加reasoning费用 |
| reasoning=separate | output不含推理，必须提供reasoning_tokens并单独计费 |
| reasoning=none | 不接受非零推理Token |

适用字段缺失、负数/小数/非法数量、缓存子集大于总输入、供应商计费身份缺失或冲突都保留风险预留；实际费用为null，不写成0。HTTP失败、输出结构不合格、租约过期隔离的响应仍提取Usage结算。超时、进程中断等不自动释放预留；在途未完成记录为reserved，缺失计量完成记录为unknown。

人工对账必须提供请求、计费身份和凭证说明，可用完整Usage按冻结价重算；也可显式提供五类 `amounts` 作为账单金额。账单只有金额没有Token时，Token保持null。实际账单超过预留时记录真实金额、标记 `ACTUAL_EXCEEDS_RESERVATION`，相关预算桶阻止新请求等待对账；不改小历史费用来制造预算内结果。

所有当前数据标注 `offline_simulation/simulated`；请求原有 `not_billable_fake` 表示并无真实供应商收费，不与模拟演算金额混淆。真实模型仍受testing+fake门禁限制，未因C05完成而开放。

## 后台与接口

`/admin/billing` 提供价格版本、预算政策、凭证对账/更正、分页费用表、独立类别流水与历史凭证、风险预留、桶预警/停发状态及CSV导出。支持小说、运行、模型能力版本、UTC日期范围、用途、币种、请求状态和费用状态筛选。配置采用可编辑JSON示例；不预填真实报价或预算金额。最近100个价格/政策版本只读展示；历史运行始终持有完整冻结版本，不依赖列表是否截断。

- GET `/api/v1/billing`：筛选结果、按币种的已核销金额/风险预留/未核销笔数；实际总额在有unknown时明确未知。
- GET `/api/v1/billing/export`：鉴权CSV费用摘要，最多一万请求，包含过滤条件；不导出密钥、请求正文或自由文本凭证。未知实际费用为空。
- POST `/api/v1/billing/price`、`/policy`、`/reconcile`：同源管理员、CSRF、Idempotency-Key，原生表单支持command_key。价格/政策需要expected_version；对账更正必须新幂等键。

完整JSON字段示例在后台与测试夹具可查。错误沿用A04 envelope，主要包括 `DEFERRED_BUDGET`、`BUDGET_CONFIGURATION_REQUIRED`、`BUDGET_RECONCILIATION_REQUIRED`、`PRICE_NOT_EFFECTIVE`、`CURRENCY_MISMATCH`、`USAGE_MISSING`、`INVALID_USAGE`、`DUPLICATE_CHARGE_ID`。

## 验证覆盖

- 精确十进制费用、极小金额舍入、缓存包含/独立、推理包含/独立、非法或缺失Usage。
- 每级预算不足时零传输、请求/预留/分配全部回滚；80%预警、100%停止；新政策不能重置已用余额。
- 两个独立PHP进程、不同小说与不同供应商，共享最后一笔日预算，只允许一个进入Fake传输。
- 超时、HTTP失败、无效结构输出、重复供应商身份；unknown不等于零，重复核销不重复记账。
- 有凭证修订、冲正和历史不可变；只有账单金额时不编造Token；账单超预留后停发。
- 六类请求用途共用门禁、价格版本冻结、未来价格/混合币种拒绝、节点级同书章节归属。
- 管理员/访客/非管理员边界、Filament HTTP渲染、Livewire筛选、费用导出和中文数据库备注。
- 全量回归包含前序模块、测试隔离、队列恢复及迁移回滚。结果见同目录JSON记录。

## 边界与待决事项

真实供应商、币种、实际预算和部署仍沿用 DEC-01/02/05，由用户在真实调用前决定。本轮未创建任何开发库测试价格或预算，未进行真实费用/文学质量验收。Token预留是容量上界法，不冒充真实tokenizer实测；真实容量与计费规则仍需独立验证。当前仅支持UTC日桶、原币独立预算，不自动换汇。

没有正式成品章和实际历史分布，不能给出可信的每千中文字符/成品章成本、修订浪费质量归因或低中高创作预测；本轮已有请求级最坏预留和用途筛选，不用虚构历史数据补齐这些后续生产指标。真实备份恢复、浏览器视觉与移动端人工验收未执行。
